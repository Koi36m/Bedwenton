2. K0 scope — permitted production changes
Implement only the shared M7/M8 plumbing needed before any visible M8 effect is introduced:
- Add the TickContributor seam to M7's RingDriver, with an optional constructor overload and TickContributor.NONE so the original M7 constructors, commands, and ring semantics continue unchanged.
- Implement or prepare the pure Java dynamic registry / effect-identity scaffolding, capacity accounting and contributor contracts required for K0. It must not introduce actual Aura, Trail, or Activation particle emissions.
- Use one M7-owned scheduler for all rings and eligible future M8 effects; no repeating task per effect, and no separate M8 planning loop.
- Enforce one shared effect cap for ring and M8 effect registrations, independently of start order. Replacement at capacity must succeed without deleting the previous effect if candidate creation or scheduler startup fails. Enforce the prospective per-player M8 cap at the registry boundary.
- Preserve correct shared-task startup, idle cancellation, shutdown, duplicate-tick and stale-callback protection, and generation-token semantics, including when M8 effects exist without rings.
- Per active tick, prune M7 rings, obtain future M8 drafts even if no ring exists, then evaluate whether any registered effects remain. Build combined requests only after identity validation; invoke at most one global DeliveryPlanner.plan per tick for any nonempty request list; when registered effects yield zero requests, skip planning but keep the scheduler alive. Keep M6 allocation-rank fairness, original recipient-prefix semantics, all global/per-viewer emission budgets, and existing style health.
- Enforce R3 identity checks on future contributor drafts and protect existing owner/session/world mappings. No invalid draft may be emitted. Do not load chunks just for VFX.
- Add opt-in M8 configuration parsing and Paper wiring/command-routing scaffolding only, as justified by K0. m8.enabled must default to false; invalid config must fail safely. Preserve M7 command grammar, suggestions, status and ring rendering with M8 disabled. Future /vfxdemo aura, trail, activate must not pretend to work; if routed during K0, respond clearly as unavailable or not yet implemented. Keep command permission checks.
- Keep any Paper-facing implementation thin and main-thread-only. Maintain safe disable/start recovery with no leaked tasks or M8 effects.
The only accepted M7 source alteration explicitly authorized is the minimal additive change to RingDriver.java and necessary supporting Paper wiring/config. Prefer isolated additions under paper-adapter/. Do not modify M1–M6, root engine source/build/tests, golden reference datasets, existing M7 tests, or established M7 behavior. 3. Nonnegotiable implementation invariants
1. Original M7 ring functions exactly as before when M8 is disabled or uses TickContributor.NONE.
2. Exactly one driver-owned scheduler; exactly one globally budgeted planner pass per tick when requests exist; none when request list is empty.
3. Global cap counts rings plus registered M8 effects, including a new M7 ring after M8 effects are already active.
4. Transactional effect start: validate and construct, ensureRunning, then commit, then dispose replaced effect. Failed first-start/replacement must preserve previous state and leave no new task behind.
5. Bound owner UUID and session viewer ID may not be substituted by snapshot contents; stale/mismatched or released identities fail closed. Implement the K0 identity guard even if there are not yet Paper-backed attached effects.
6. No unbounded collections, no chunk loading, no asynchronous Bukkit access, no independent budget resets or particle broadcasting.
7. Preserve original M7 stop, quit, death, world change, world unload, and plugin disable cleanup behavior.
