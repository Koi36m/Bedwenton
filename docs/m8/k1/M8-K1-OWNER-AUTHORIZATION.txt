4. Motion and attachment

Implement a player-attached aura using the accepted M1–M6 engine.

Use:

M1 Pose and Quaternion mathematics.

M2 deterministic tick timing.

M3 rotation and motion geometry.

M4 uniform sampling.

M5 scene composition and evaluation.

M6 global particle budgeting.

M7 emitter and recipient authorization.

K0 DynamicEffectRegistry, AnchorSnapshot, and shared TickContributor.

The effect must:

Follow the player while walking.

Follow while sprinting.

Follow vertical movement, including jumping and falling.

Respond correctly to body yaw.

Remain horizontal when the player changes pitch.

Update its anchor from a fresh validated snapshot every tick.

Maintain deterministic rotation relative to its original start tick.

Avoid unnecessary geometry rebuilding each tick.

Use the accepted orientation convention:

Local +X = left.

Local +Y = up.

Local +Z = forward.

Body yaw determines horizontal orientation.

Never infer ownership from untrusted snapshots.

World changes

Preserve the accepted R3 behavior: the aura continues in the new world using the next valid snapshot, provided the owner remains eligible.

It must snap to the new position without creating a particle streak between worlds.

Death, disconnect, expiration, explicit cancellation, or plugin shutdown terminate the aura.

Do not recalculate particle geometry unnecessarily.
