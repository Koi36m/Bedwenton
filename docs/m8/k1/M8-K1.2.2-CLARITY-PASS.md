# K1.2.2 — white sigil clarity pass

Owner-authorized scope: reduce END_ROD crowding; preserve the verified K1.2.1 layout and all gameplay/security boundaries.

Paper's ordinary particle API does not expose a per-spawn END_ROD lifetime override. This pass changes emission cadence,
not the vanilla client particle lifetime. White outline and inner strokes emit once every **4 game ticks**, at effect
ages 0, 4, 8, ... while active. A missed or rejected tick is not replayed. Replacing an aura starts a new age-zero pulse.

Rotation uses the original Playback, current TimePoint and frameOrdinal on every contribution: no phase accumulation,
pausing, slowed rotation, extra timer or scheduled task. All emitted positions retain radius 1.05, rear offset 0.85,
center height 1.25, vertical rear plane, stable outline and the 80-tick inner rotation. No new particles or layers.
The cyan halo's layer, shape, motion, color, size and every-tick cadence remain unchanged.

| Tier | Full pulse total | White points per pulse | Halo points every tick | Total on intervening ticks |
|---|---:|---:|---:|---:|
| Simple |20|20|0|0|
| Balanced |34|28|6|6|
| Heavy |44|36|8|8|

AuraSession caches two immutable recipes once: the original full recipe and a non-pulse recipe reusing the exact halo
Layer objects. AuraEffect selects one using `(tick - startTick) % 4 == 0`, after the existing lifecycle/identity checks.
The non-pulse Simple variant has no layers. The registered effect still contributes and receives validation/expiry
checks every tick. No platform object, timer, counter, mutable global, new public API or new dependency is introduced.

White points are omitted **before M6 admission/evaluation**, so they reserve no generation or placement budget on
non-pulse ticks and are not falsely counted as successful sends or emitter skips. The existing one global M6 plan,
fairness/thinning, tier ceilings, reservations and adapter accounting equations are unchanged. An empty Simple variant
gets the existing M6 SKIPPED_UNSUPPORTED outcome with zero reservation/points/placements; it remains registered until
the normal lifecycle removes it. Disabled halo-only variants likewise use existing M6 outcomes. No false failures or
health updates are introduced. Other effects can use budget freed by the omitted white points; under tight budgets,
halo delivery can consequently improve, without changing its geometry or cadence policy.

All 603 prior test identifiers remain. Cadence-specific expectations and recipe-cache assertions are updated explicitly.
Continuous geometry tests evaluate the unchanged full AuraRecipe at every phase, independently of the cadence gate;
eight new tests exercise actual runtime contributions and sends at both cadences, captured halo bit values, rotation,
start-relative/missed ticks, cached variants, global ring budgets, permissions, invalid identities and lifecycle cleanup.
Numerical epsilon tolerances, frozen M1–M6 expectations, M7/K0 tests and reference datasets/generators stay unchanged.
